# 감리체크리스트 출처문헌 및 근거조사

## Overview

정보시스템 감리(클라우드전환/운영 및 유지관리/생성형AI 사업) 검토항목 체크리스트에 **출처문헌**과 **근거 및 상세내용**을 조사하여 보강하는 기술 스킬. 목적은 검토항목의 객관성과 신뢰성 확보 — 근거 없는 검토항목은 감리 결과의 정당성을 약화시킨다.

**핵심 원칙: 근거를 지어내지 않는다.** 확인되지 않은 법령 조항, 실재하지 않는 가이드/표준을 그럴듯하게 인용하면 검토항목의 신뢰성이 오히려 무너진다. 실제로 원문을 확인한 문헌만 인용하고, 확인 불가능하면 "확인 필요"로 명시한다.

## When to Use

- 사용자가 검토항목(체크리스트) 파일을 업로드하고 출처문헌/근거 조사를 요청할 때
- 검토항목에 "출처 문헌", "근거 및 상세 내용" 항목이 비어있거나 부실할 때
- 클라우드전환사업, 운영 및 유지관리 사업, 생성형 AI 사업 감리 관련 체크리스트일 때

**사용 안 함**: 검토항목 자체를 새로 설계하는 작업, 감리 결과 판정/평가서 작성

## Quick Reference

| 단계 | 내용 |
|---|---|
| 1. 입력 확인 | 검토항목 파일 + 사용자 업로드 우선 출처문헌 확보 |
| 2. 출처 조사 | 우선 문헌 → 부족 시 법령정보센터/가이드/ISO/TTA/논문/도서 |
| 3. 항목별 작성 | 검토 내용 유지, 출처문헌+근거 추가 (형식은 아래 참고) |
| 4. 저장 | markdown, `[원본파일명]_출처근거조사.md` |
| 5. 누락 검증 | 원본 일련번호 전체 vs 작성 완료 일련번호 비교, **결과물 파일에 기록** |

## Workflow

### 1. 입력 확인

- 검토항목 파일 경로 확보 (없으면 사용자에게 요청)
- 사용자가 우선 검토용으로 업로드한 출처문헌이 있는지 확인 — 있으면 1순위로 사용

### 2. 출처 조사 순서 (Source Priority)

각 검토항목마다 아래 순서로 조사한다. 앞 단계에서 충분한 근거를 찾으면 다음 단계로 넘어가지 않아도 된다.

1. **사용자 업로드 출처문헌** — 해당 검토항목을 뒷받침하는 조항/내용이 있는지 먼저 확인.
2. **위 문헌으로 근거가 불충분한 경우**, 아래를 확인:
   - 대한민국 법령정보센터(law.go.kr) — 정보화사업 관련 법률/시행령/시행규칙/고시
   - 정보화사업 관련 정부·공공기관 가이드 (예: NIA, 행안부, 과기정통부 가이드)
   - ISO 국제표준 (해당 분야 관련 시리즈)
   - TTA 국가표준(정보통신단체표준)
   - 학술 논문
   - 관련 도서

### 3. 검토항목별 결과 작성

원본 검토항목의 일련번호·제목·검토 내용은 그대로 유지하고, 출처문헌/근거만 추가한다:

```markdown
#### [일련번호]: [검토항목 제목]
* **검토 내용**: [원본 검토 내용 그대로]
* **출처 문헌**:
    * [법령명 제O조(조항명) / 가이드명 / 표준번호 등 — 실제 확인한 것만]
* **근거 및 상세 내용**:
    * [해당 출처가 왜/어떻게 이 검토항목을 뒷받침하는지 구체적 설명]
```

출처를 찾지 못한 항목은 출처문헌란에 `- 확인 필요 (사유: ...)` 로 명시한다. 그럴듯한 문헌을 임의로 지어내지 않는다.

### 4. 결과물 저장

- markdown 문서로 저장 (원본 파일과 같은 위치), 파일명: `[원본파일명]_출처근거조사.md`
- 원본의 항목 구조(대분류-중분류-세부번호 등)를 그대로 유지

### 5. 누락 검증 (완료 후 필수)

작업이 끝나면 반드시 아래를 수행한다:

1. 원본 검토항목 파일에서 모든 일련번호를 추출한다.
2. 결과물 markdown에서 "출처 문헌"이 작성된 일련번호를 추출한다.
3. 두 목록을 비교하여 누락된 일련번호가 있는지 확인한다.
4. 누락이 있으면 마저 작성하거나, 사용자에게 누락 목록을 명시적으로 보고한다.
5. 이 비교 결과(전체 개수 vs 작성된 개수, 누락 목록)를 **결과물 markdown 파일 하단에 별도 섹션으로 기록**한다 — 채팅 답변으로 구두 보고하는 것만으로는 불충분하다. 문서에 기록되지 않은 검증은 수행하지 않은 것으로 간주한다.
6. "완료했다"고 보고하기 전에 이 문서화된 비교 결과를 실제로 확인한다. 개수 비교 없이 완료를 선언하지 않는다.

## Common Mistakes

| 실수 | 결과 / 대응 |
|------|------|
| 그럴듯하지만 실제로 원문 확인 안 한 법조항·표준 인용 | 감리 근거의 신뢰성 붕괴. 실제 원문을 확인한 것만 인용, 안 되면 "확인 필요" |
| 일부 항목만 처리하고 "완료"로 보고 | 5단계 누락 검증 없이 완료 선언 금지 |
| 사용자가 업로드한 우선 문헌을 건너뛰고 바로 법령정보센터부터 검색 | 우선순위(1순위 업로드 문헌) 무시 — 반드시 먼저 확인 |
| 원본 검토항목의 제목/검토 내용을 임의로 수정 | 원본은 그대로 두고 출처/근거만 추가 |
