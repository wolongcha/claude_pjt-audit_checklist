## 1. Agentic AI 아키텍처 설계
- 01. Agentic AI 구조가 요구사항에 맞게 설계되었는가? [3-2-다-1-01]
- Agent, LLM, RAG, Tool/API, 업무시스템 간 연계 구조 설계
- 단일 Agent / 다중 Agent 적용 범위 구분
- 챗봇, 지식검색, 문서생성, 업무자동화별 Agent 구조 반영
- 02 Agent 실행 흐름이 통제 가능하게 설계되었는가? [3-2-다-1-02]
- 사용자 요청 → 의도분석 → 계획수립 → Tool 호출 → 결과검증 → 응답 흐름 정의
- 단계별 로그 및 추적정보 저장 구조
- Agent 실행 중단, 재시도, 예외처리 구조
## 2. MCP 연계 설계
- 01. MCP 기반 Tool 연계 구조가 적정하게 설계되었는가? [3-2-다-2-01]
- MCP Server, MCP Client, Tool Registry 구성 정의
- Agent별 호출 가능한 Tool 목록 및 권한 범위 정의
- Tool 입력값·출력값·호출조건·응답형식 표준화
- 02. MCP Tool 호출 통제가 설계되었는가? [3-2-다-2-02]
- 사용자 권한 기반 Tool 호출 제한
- 민감정보 포함 요청의 Tool 호출 차단
- 외부 API 또는 외부 LLM 연계 Tool의 보안 검토 절차
- 03. MCP 실행 로그 및 감사추적이 가능한가? [3-2-다-2-03]
- Tool 호출 이력, 파라미터, 응답값, 오류 로그 저장
- Tool 호출 승인·차단·실패 이력 관리
- 사고 발생 시 호출 경로 역추적 가능성
## 3. A2A 연계 설계
- 01. Agent 간 통신 구조가 명확하게 설계되었는가? [3-2-다-3-01]
- Agent 간 역할, 호출 순서, 메시지 형식 정의
- 요청 Agent, 수행 Agent, 검증 Agent 간 책임 경계
- Agent 간 데이터 전달 범위 및 제한 기준
- 02. A2A 호출 통제 및 충돌 방지 구조가 설계되었는가? [3-2-다-3-02]
- 중복 호출, 무한 루프, 반복 실행 방지 기준
- Agent 간 상충 결과 발생 시 우선순위 기준
- 호출 실패·지연·타임아웃 처리 기준
- 03. A2A 결과 검증 및 책임추적 구조가 마련되었는가? [3-2-다-3-03]
- Agent별 처리 결과와 최종 응답 간 정합성 검증
- Agent 간 호출 이력 및 의사결정 경로 기록
- 최종 응답 생성 책임 Agent 식별
## 4. Agent–RAG 연계 설계
- 01. Agent와 RAG 검색 연계가 적정하게 설계되었는가? [3-2-다-4-01]
- Agent가 호출할 RAG 대상 데이터 및 검색 범위 정의
- 기록물관리, 민원통합, 사규, FAQ별 호출 기준
- 검색 결과를 Agent 응답에 반영하는 기준
- 02. 검색 결과 검증 및 근거 활용 구조가 설계되었는가? [3-2-다-4-02]
- Agent가 활용한 근거 문서의 출처 표시
- 관련도 낮은 검색 결과 제외 기준
- 근거 부족 시 추가질의 또는 답변 제한 구조
## 5. Agent–Tool/API 연계 설계
- 01. Agent가 호출할 Tool/API 범위가 적정하게 설계되었는가? [3-2-다-5-01]
- 내부 업무시스템 API, 검색 API, 문서생성 Tool, 외부 API 범위 정의
- Tool별 입력값, 출력값, 호출조건 정의
- Agent별 사용 가능한 Tool 목록 및 권한 범위
- 02. Tool 호출 결과 검증 구조가 마련되었는가? [3-2-다-5-02]
- Tool 응답값의 유효성 검증 기준
- Tool 호출 실패, 지연, 중복 호출 대응 구조
- Tool 결과와 Agent 응답 간 정합성 검증
## 6. 계획 수립 및 실행 통제 설계
- 01. Agent의 계획 수립 로직이 통제 가능하게 설계되었는가? [3-2-다-6-01]
- 사용자 요청을 처리 단계로 분해하는 기준
- 다단계 업무 수행 시 실행 순서 및 조건 정의
- 계획 변경 또는 중단 기준
- 02. Agent의 자율 실행 범위가 제한되어 있는가? [3-2-다-6-02]
- 자동 실행 가능 업무와 승인 필요 업무 구분
- 민원 접수, 외부 전송, 문서 확정 등 사용자 승인 지점
- 고위험 업무의 자동처리 제한 기준
## 7. 다중 Agent 협업 설계
- 01. 다중 Agent 구성 및 역할 분담이 적정한가? [3-2-다-7-01]
- 검색 Agent, 응답 Agent, 문서생성 Agent, 검증 Agent 역할 구분
- Agent 간 호출 순서 및 데이터 전달 구조
- Agent 간 책임 경계 및 예외처리 기준
- 02. Agent 간 충돌 및 중복 실행 방지 구조가 설계되었는가? [3-2-다-7-02]
- 동일 요청에 대한 중복 Tool 호출 방지
- 상충 결과 발생 시 우선순위 기준
- 반복 실행, 무한 루프, 과도한 호출 방지
## 8. Agent 보안 및 권한 설계
- 01. Agent 실행 권한이 적정하게 설계되었는가? [3-2-다-8-01]
- 사용자·부서·직무별 Agent 사용 권한
- Agent별 접근 가능한 데이터 및 Tool 범위
- 관리자·운영자·일반사용자 권한 분리
- 02. Agent 오남용 방지 구조가 설계되었는가? [3-2-다-8-02]
- 권한 없는 데이터 조회 및 Tool 호출 차단
- 프롬프트 인젝션에 의한 Tool 오용 방지
- Agent 실행 횟수, 호출 빈도, 자원 사용 제한
## 9. Human-in-the-Loop 설계
- 01. 사람 검토 및 승인 지점이 명확히 설계되었는가? [3-2-다-9-01]
- 민원 답변, 문서생성, 외부 전송 등 승인 필요 업무 정의
- Agent 결과의 담당자 검토·수정·확정 절차
- 자동처리와 수동처리 전환 기준
- 02. Agent 실패 시 인간 개입 절차가 설계되었는가? [3-2-다-9-02]
- 정보 부족, 권한 부족, 오류 발생 시 담당자 연결
- 반복 실패 또는 민감 민원 발생 시 escalation 기준
- 사용자 불만 및 오답 신고 처리 절차
## 10. Agent 품질 및 성능평가 설계
- 01. Agent 품질평가 기준이 설계되었는가? [3-2-다-10-01]
- Agent 응답 정확성, 완전성, 일관성 기준
- 업무처리 결과와 근거 문서 간 정합성 기준
- 대민 서비스와 내부 업무 Agent 품질 기준 구분
- 02. Agent 성능평가 기준이 마련되었는가? [3-2-다-10-02]
- Agent 응답시간, Tool 호출시간, 전체 처리시간 기준
- MCP Tool 호출 및 A2A 통신 지연시간 기준
- 성공률, 실패율, 재시도율, 사용자 만족도 지표
## 11. Agent 운영 및 모니터링 설계
- 01. Agent 운영관리 구조가 설계되었는가? [3-2-다-11-01]
- Agent 등록·변경·배포·중지 절차
- Agent 버전관리 및 변경관리 기준
- Agent별 담당자 및 운영 책임 정의
- 02. Agent/MCP/A2A 모니터링 체계가 설계되었는가? [3-2-다-11-02]
- Agent 실행 건수, 성공률, 실패율, 오류율 모니터링
- MCP Tool 호출 성공률, 지연시간, 장애율 모니터링
- A2A 호출 흐름, 반복 호출, 비정상 실행 탐지
## 12. Agent 설계 산출물 및 증적관리
- 01. Agent 설계 산출물이 완비되었는가? [3-2-다-12-01]
- Agent 아키텍처 설계서, Agent 목록, 업무 시나리오 정의서
- MCP Tool/API 목록, 호출조건, 권한 매트릭스
- A2A 메시지 정의서, Agent 간 호출흐름도, 오류처리 기준
