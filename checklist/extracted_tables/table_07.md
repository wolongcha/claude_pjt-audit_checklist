## 1. 범위 및 과업 반영 관리 적정성
- 01. 요구정의 단계에서 확정된 클라우드 전환 범위가 설계 산출물에 반영되어 있는가? [1-2-가-1-01]
- 전환 대상 시스템, 업무, 서비스, 인프라 범위가 설계서에 반영되어 있는지 확인
- 요구사항정의서와 설계서 간 범위 불일치가 없는지 확인
- 전환 제외·보류 대상과 그 사유가 설계 산출물에 명확히 반영되어 있는지 확인
- 02. 계약·제안·요구사항과 설계 산출물 간 과업 범위 불일치가 없는가? [1-2-가-1-02]
- RFP, 제안서, 계약서, 요구사항정의서, 설계서 간 정합성 확인
- 클라우드 인프라, 플랫폼, 애플리케이션, 데이터, 네트워크·보안 설계 범위 누락 여부 확인
- 과업 범위 변경이 필요한 경우 변경관리 절차에 따라 승인되었는지 확인
- 03. 추가·변경 요구사항이 공식 절차에 따라 설계에 반영되고 있는가? [1-2-가-1-03]
- 변경요청 등록, 영향도 분석, 승인 절차 수행 여부 확인
- 변경사항이 일정, 비용, 품질, 테스트 계획에 반영되었는지 확인
- 승인되지 않은 임의 설계 변경 또는 구두 합의 변경 여부 확인
## 2. 일정 및 진척관리 적정성
- 01. 설계단계 이후 주요 활동 일정이 체계적으로 수립되어 있는가? [1-2-가-2-01]
- 설계 이후 일정 수립 상세화 여부
- 산출물 작성·검토·승인 일정이 전체 전환 일정과 연계되어 있는지 확인
- 설계 일정 조정 등이 구축·전환·테스트 일정에 반영되었는지 확인
- 02. 설계 검토·보완·승인 일정이 관리되고 있는가? [1-2-가-2-02]
- 설계 검토회의 일정, 검토 대상, 승인권자 정의 여부 확인
- 설계 보완사항의 조치기한과 담당자가 지정되어 있는지 확인
- 구축 착수 등 선행 착수 위험이 없는지 확인
- 03. 미확정 설계 항목과 의사결정 필요사항이 이슈로 관리되고 있는가? [1-2-가-2-03]
- 미결정 항목, 쟁점사항, 외부 협의 필요사항 목록화 여부 확인
- 의사결정 담당자, 조치기한, 승인결과 관리 여부 확인
- 미확정 항목이 후속 구축단계로 이월될 경우 위험과 대응방안이 정의되어 있는지 확인
## 3. 이해관계자 관리 및 역할 할당 적정성
- 01. 설계단계 이후 이해관계자별 역할과 책임이 명확히 정의되어 있는가? [1-2-가-3-01]
- 발주기관, 수행사, CSP/MSP, 운영조직, 보안담당자 역할 정의 여부 확인
- 영역별 설계 작성자, 검토자, 승인자 지정 여부 확인
- 책임 공백 또는 중복 책임 발생 가능성 확인
- 02. CSP/MSP, 수행사, 발주기관 간 책임 범위가 설계에 반영되어 있는가? [1-2-가-3-02]
- 책임분계표 작성 여부 확인
- 장애, 보안, 성능, 데이터 손실 발생 시 책임 주체 명확성 확인
- 공동책임 모델 또는 외부 사업자 책임 범위가 설계에 반영되어 있는지 확인
- 03. 영역별 설계 책임자가 지정되어 있는가? [1-2-가-3-03]
- 클라우드 인프라, 플랫폼, 애플리케이션, 데이터, 네트워크, 보안 영역별 책임자 지정 여부 확인
- 영역 간 설계 조정 책임과 통합 검토 책임이 정의되어 있는지 확인
- 외부 사업자 또는 상용SW 공급사 설계 참여 범위가 명확한지 확인
## 5. 요구사항 추적성 관리
- 01. 요구사항별 설계 반영 여부가 추적 관리되고 있는가? [1-2-가-5-01]
- 설계단계까지 요구사항 추적표 작성 여부 확인
- 요구사항별 설계 반영, 부분반영, 미반영 상태 관리 여부 확인
- 미반영 요구사항의 사유와 대체방안 승인 여부 확인
- 02. 요구사항–설계–테스트 간 연계성이 확보 체계가 확보되어 있는가? [1-2-가-5-02]
- 요구사항별 검증 항목이 도출되어 있는지 확인
- 설계까지의 연계 내용에 대한 추적성 확보 여부
- 종료단계에서 요구사항 충족 여부를 검증할 수 있는 검사 기준 마련 여부
## 8. 위험 및 이슈관리 적정성
- 01. 설계단계 주요 전환 위험이 식별되어 있는가? [1-2-가-8-01]
- 플랫폼 변경, IP 변경, 상용SW 호환성, 데이터 복제 지연, 보안정책 오류 위험 확인
- 연계기관 협의 지연, 라이선스 이슈, 기술지원 지연 위험 확인
- 전환 실패, 성능 미달, 원복 실패 가능성 식별 여부 확인
- 02. 위험별 영향도, 대응방안, 담당자가 정의되어 있는가? [1-2-가-8-02]
- 위험 발생 가능성 및 영향도 평가 여부 확인
- 예방·완화·대응 방안 수립 여부 확인
- 담당자, 조치기한, 상태값 관리 여부 확인
- 03. 설계 미확정, 기술검토 지연, 외부협의 이슈가 관리되고 있는가? [1-2-가-8-03]
- 미확정 설계 항목의 조치계획 관리 여부 확인
- CSP/MSP, 상용SW 공급사, 외부기관 협의 필요사항 관리 여부 확인
- 중대 이슈의 escalation 및 의사결정 체계 운영 여부 확인
## 9. 변경관리의 적정성
- 01. 설계단계 변경사항이 공식 변경요청으로 관리되고 있는가? [1-2-가-9-01]
- 요구사항, 구성, 전환방식, 일정, 비용, 보안정책 변경 등록 여부 확인
- 변경 사유, 요청자, 영향도, 승인자 기록 여부 확인
- 승인 전 임의 변경 적용 여부 확인
- 02. 변경 승인 후 관련 산출물이 함께 갱신되고 있는가? [1-2-가-9-02]
- 설계서, 구성도, 정책표, 테스트계획, 요구사항 추적표 갱신 여부 확인
- 변경 이력 및 승인 이력 관리 여부 확인
- 최신 산출물 기준으로 후속 작업이 진행되는지 확인
## 6. 전환 계획 및 절차관리
- 01. 클라우드 전환 실행을 위한 단계별 전환 시나리오가 설계되어 있는가? [1-2-가-6-01]
- 사전 준비, 리허설, 본 전환, 검증, 오픈 절차 정의 여부 확인
- 애플리케이션, 데이터, 인프라, 네트워크·보안 전환 순서가 연계되어 있는지 확인
- 단계별 책임자, 작업시간, 승인기준이 정의되어 있는지 확인
## 4. 설계 산출물 품질관리
- 01. 설계단계 주요 산출물이 작성 기준에 따라 작성되어 있는가? [1-2-가-4-01]
- 클라우드 아키텍처 설계서, 인프라 구성도, 플랫폼 설계서 작성 여부 확인
- 애플리케이션 전환설계서, 데이터 이관·복제 설계서, 네트워크·보안 설계서 작성 여부 확인
- 테스트 계획서, 전환 계획서, 원복 계획서 등 후속 검증 산출물 작성 여부 확인
- 02. 산출물별 작성자·검토자·승인자가 명확히 지정되어 있는가? [1-2-가-4-02]
- 산출물 책임자 지정 여부 확인
- 검토 및 승인 이력 관리 여부 확인
- 미승인 산출물이 후속 단계에 사용되지 않도록 통제되는지 확인
- 03. 설계서 변경 이력과 검토의견이 관리되고 있는가? [1-2-가-4-03]
- 설계 산출물 버전관리 및 변경이력 관리 여부 확인
- 검토의견, 조치결과, 재검토 결과 기록 여부 확인
- 최신본 기준으로 설계·구축·테스트가 진행되도록 관리되는지 확인
## 10. 품질보증 활동 수행관리
- 01. 설계 품질보증 활동이 계획대로 수행되고 있는가? [1-2-가-10-01]
- 계획된 산출물 리뷰 수행 여부 확인
- 체크리스트 기반 품질점검 수행 여부 확인
- 품질보증 결과와 조치이력 관리 여부 확인
- 02. 품질보증 담당자가 설계 산출물의 완전성·일관성·추적성을 검토하고 있는가? [1-2-가-10-02]
- 산출물 누락 여부 확인
- 산출물 간 불일치 점검 여부 확인
- 요구사항 추적성과 테스트 가능성 확인 여부
- 03. 설계 결함과 보완사항이 조치되고 재검토되고 있는가? [1-2-가-10-03]
- 보완 요청사항 등록 여부 확인
- 조치결과 확인 여부 확인
- 재검토 및 승인 결과 관리 여부 확인
- 04. 품질보증 결과가 구축 착수 판단에 활용되고 있는가? [1-2-가-10-04]
- 설계단계 완료 기준 충족 여부 확인
- 구축 착수 전 필수 보완사항 조치 여부 확인
- 단계전환 승인 근거 확보 여부 확인
