- 카테고리: 라. 개발SW 유지관리

## 1. 유지관리 수행절차 설계
- 01. 개발SW 유지관리 절차가 실행 가능한 수준으로 설계되어 있는가? [2-2-라-1-01]
- 요청 접수, 분석, 승인, 수정, 테스트, 배포, 종료 절차가 설계되어 있는지 확인
- 오류수정, 기능개선, 성능개선, 데이터 수정 요청별 처리절차가 구분되어 있는지 확인
- 정기 유지관리와 긴급 유지관리의 절차 및 승인 기준이 반영되어 있는지 확인
- 02. 운영과 유지관리 간 업무 인계 기준이 설계되어 있는가? [2-2-라-1-02]
- 운영 중 장애가 개발SW 유지관리 요청으로 전환되는 기준이 반영되어 있는지 확인
- 단순문의, 장애, 오류수정, 기능개선 간 분류 기준이 설계되어 있는지 확인
- 운영팀, 유지관리팀, 업무부서 간 요청 이관 및 결과확인 절차가 반영되어 있는지 확인
## 2. CSR 처리 설계
- 01. CSR 처리 프로세스가 구체적으로 설계되어 있는가? [2-2-라-2-01]
- CSR 접수, 분류, 우선순위 부여, 영향도 분석, 승인 절차가 반영되어 있는지 확인
- 오류수정, 기능변경, 데이터 정정, 업무지원 요청별 처리 기준이 설계되어 있는지 확인
- CSR 처리기한, 승인권자, 종료 기준, 사용자 확인 기준이 반영되어 있는지 확인
## 3. 프로그램 수정 및 테스트 설계
- 01. 프로그램 수정 절차와 기준이 설계되어 있는가? [2-2-라-3-01]
- 소스 수정 기준, 개발표준, 명명규칙, 주석, 보안코딩 기준이 반영되어 있는지 확인
- 수정 대상 기능, 화면, 배치, 연계 프로그램 식별 기준이 설계되어 있는지 확인
- 긴급수정 시 사전·사후 승인 절차가 반영되어 있는지 확인
## 4. 형상·배포 관리 설계
- 01. 수정 프로그램의 형상관리 및 배포관리 체계가 설계되어 있는가? [2-2-라-4-01]
- 소스, 설정파일, 배포파일, 라이브러리 버전관리 기준이 반영되어 있는지 확인
- 개발·검증·운영 환경 간 형상 일치 기준이 설계되어 있는지 확인
- 정기배포, 긴급배포, 임시배포 구분 기준과 원복 절차가 반영되어 있는지 확인
