# Table 11
- 도메인: 1. 클라우드 전환 사업
- 단계: 2. 설계 단계
- 카테고리: 마. 클라우드 인프라

## 1. 목표 인프라 아키텍처 설계
- 01. 클라우드 전환 대상 시스템의 목표 인프라 아키텍처가 요구사항에 맞게 설계되어 있는가? [1-2-마-1-01]
- 업무시스템별 서버, 스토리지, 네트워크, 보안 구성 반영 여부
- 운영, 개발, 검증, DR 환경 구분 여부
- 현행 인프라와 목표 클라우드 인프라 간 차이 반영 여부
- 02. Web/WAS/DB, 배치, 연계, 관리 서버 등 주요 구성요소가 적정하게 배치되어 있는가? [1-2-마-1-02]
- 업무 특성별 서버 역할 분리 여부
- 중요 업무와 일반 업무의 자원 분리 여부
- 장애 전파 방지를 위한 구성요소 격리 여부
- 03. 인프라 구성도와 상세 설계서 간 정합성이 확보되어 있는가? [1-2-마-1-03]
- 서버명, IP, 자원규격, 연결관계 일치 여부
- 네트워크·보안 설계와 인프라 설계 간 불일치 여부
- 구성 변경 이력 및 설계 승인 여부
## 2. 컴퓨팅 자원 설계
- 01. 업무 처리량과 성능 요구사항을 반영하여 컴퓨팅 자원이 산정되어 있는가? [1-2-마-2-01]
- vCPU, 메모리, 인스턴스 수량 산정 기준 확인
- 사용자 수, 동시접속자 수, 트랜잭션량 반영 여부
- 피크 시간, 월말·연말 처리, 대량 배치 부하 반영 여부
- 02. 컴퓨팅 자원의 확장 및 축소 기준이 설계되어 있는가? [1-2-마-2-02]
- 수평확장, 수직확장 적용 기준 정의 여부
- 오토스케일링 적용 대상과 임계치 정의 여부
- 03. 업무 중요도에 따라 컴퓨팅 자원이 적절히 분리·할당되어 있는가? [1-2-마-2-03]
- 핵심 업무와 비핵심 업무 자원 분리 여부
- 운영·검증·개발 환경 자원 분리 여부
## 3. 스토리지 및 백업 인프라 설계
- 01. 스토리지 구성과 용량이 데이터 특성에 맞게 설계되어 있는가? [1-2-마-3-01]
- 블록, 파일, 오브젝트 스토리지 적용 기준 확인
- DB, 첨부파일, 로그, 백업 데이터별 저장소 구분 여부
- 용량 증가율, 보관기간, IOPS 요구사항 반영 여부
- 02. 백업 대상, 주기, 보관기간, 복구 방식이 명확히 설계되어 있는가? [1-2-마-3-02]
- 서버, DB, 파일, 설정정보, 로그 백업 대상 정의 여부
- 일·주·월 백업 주기 및 보관정책 반영 여부
- 백업 데이터의 보관 위치와 접근권한 정의 여부
## 4. 고가용성 및 이중화 설계
- 01. 주요 인프라 구성요소의 고가용성 구조가 설계되어 있는가? [1-2-마-4-01]
- 서버, DB, 스토리지, 네트워크 이중화 여부
- Load Balancer, 이중 NIC, 다중 AZ/Zone 적용 여부
- 중요도별 가용성 수준 차등 적용 여부
- 02. 단일 장애점(SPOF)이 식별되고 제거 방안이 반영되어 있는가? [1-2-마-4-02]
- 단일 서버, 단일 스토리지, 단일 회선 위험 식별 여부
- 장애 시 우회 경로 또는 대체 자원 설계 여부
- SPOF 제거 불가 항목의 예외 사유와 대응방안 명시 여부
## 5. 성능 및 용량 설계
- 01. 인프라 성능 목표와 측정 기준이 정량적으로 설계되어 있는가? [1-2-마-5-01]
- CPU, 메모리, 디스크, 네트워크 사용률 기준 정의 여부
- 응답시간, 처리량, 동시사용자 기준 반영 여부
- 성능시험 시나리오와 합격 기준 정의 여부
- 02. 용량 산정이 현재 사용량과 향후 증가량을 반영하고 있는가? [1-2-마-5-02]
- 현행 자원 사용량 분석 결과 반영 여부
- 데이터 증가율, 로그 증가율, 백업 용량 증가 반영 여부
- 용량 부족 예상 시 증설 기준과 절차 정의 여부
## 6. 네트워크 인프라 연계 설계
- 01. 클라우드 인프라와 내·외부 시스템 간 네트워크 연결 구조가 설계되어 있는가? [1-2-마-6-01]
- VPC, 서브넷, 라우팅, NAT, DNS 구성 반영 여부
- 내부망, 외부망, 관리망, 연계망 구분 여부
- 온프레미스, 외부기관, 공통기반 연계 구조 반영 여부
- 02. 인프라 관점의 IP, 포트, 방화벽 요구사항이 설계에 반영되어 있는가? [1-2-마-6-02]
- 서버별 IP, 포트, 프로토콜 정의 여부
- 방화벽 정책, 보안그룹, ACL 반영 여부
- 포트 허용 신청 및 검증 절차 정의 여부
- 03. 네트워크 성능 및 안정성 확보 방안이 설계되어 있는가? [1-2-마-6-03]
- 대역폭, 지연시간, 패킷 손실 기준 정의 여부
- 이중회선, 우회경로, 장애전환 방안 반영 여부
- 대용량 데이터 이관 또는 배치 시 네트워크 부하 검토 여부
## 7. 인프라 보안 설계
- 01. 클라우드 인프라 보안 설정 기준이 설계에 반영되어 있는가? [1-2-마-7-01]
- OS 보안설정, 계정정책, 패치 기준 정의 여부
- 불필요 서비스 차단, 기본 계정 제거 여부
- 서버 접근통제와 관리자 권한 관리 기준 반영 여부
## 8. 인프라 구축 및 검증 설계
- 01. 클라우드 인프라 구축 절차가 실행 가능한 수준으로 설계되어 있는가? [1-2-마-8-01]
- 서버 생성, 스토리지 연결, 네트워크 구성, 보안정책 적용 순서 정의 여부
- 작업 담당자, 작업 시간, 승인자 명시 여부
- 구축 전·중·후 점검항목 정의 여부
- 02. 인프라 구성 검증 항목이 구체적으로 정의되어 있는가? [1-2-마-8-02]
- 자원규격, OS, 네트워크, 방화벽, 접근권한 검증 여부
- 백업, 모니터링, 로그수집, 보안설정 검증 항목 반영 여부
- 구축 결과와 설계서 간 일치 여부 확인 기준
- 03. 통합테스트와 성능시험에 인프라 검증 항목이 포함되어 있는가? [1-2-마-8-03]
- 사용자 시나리오 기반 인프라 성능 검증 여부
- 연계시스템 접속 및 호환성 검증 여부
- 부하, 장애전환, 백업복구 시험 반영 여부
