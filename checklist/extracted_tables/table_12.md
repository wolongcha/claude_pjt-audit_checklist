## 1. 목표 네트워크 아키텍처 설계
- 01. 클라우드 전환 후 목표 네트워크 아키텍처가 요구사항에 맞게 설계되어 있는가? [1-2-바-1-01]
- VPC/VNet, 서브넷, 라우팅, NAT, DNS 구성 반영 여부
- 내부망, 외부망, 관리망, 연계망 분리 설계 여부
- 운영, 개발, 검증, DR 환경별 네트워크 분리 여부
- 02. 현행 네트워크와 목표 클라우드 네트워크 간 연결 구조가 명확히 설계되어 있는가? [1-2-바-1-02]
- 온프레미스–클라우드 간 연결 방식 정의 여부
- 전용회선, VPN, Peering, 보안터널 적용 여부
- 네트워크 경로, 라우팅, 게이트웨이 구성 명확성 확인
- 03. 네트워크 구성도와 상세 설계서 간 정합성이 확보되어 있는가? [1-2-바-1-03]
- IP 대역, 서브넷, 라우팅, 방화벽 정책 일치 여부
- 서버 구성도, 보안설계서, 연계설계서 간 불일치 여부
- 변경 이력과 승인 이력 관리 여부
## 2. IP·DNS·
도메인 변경 설계
- 01. IP 변경 대상과 변경 방식이 설계 산출물에 명확히 반영되어 있는가? [1-2-바-2-01]

- IP 변경에 따른 애플리케이션·연계 영향 반영 여부
- 02. DNS, 도메인, URL 변경 방안이 설계되어 있는가? [1-2-바-2-02]
- 내부 DNS, 외부 DNS, 도메인 변경 대상 식별 여부
- 서비스 URL, Callback URL, API Endpoint 변경 반영 여부
- DNS 전환 시점, TTL 조정, 전파 확인 절차 정의 여부
## 3. 라우팅 및 트래픽 흐름 설계
- 01. 업무 트래픽 흐름이 목표 구조에 맞게 설계되어 있는가? [1-2-바-3-01]
- 사용자–LB–Web/WAS–DB 구간 트래픽 흐름 정의 여부
- 내부망·외부망·관리망 간 통신 경로 구분 여부
- 대외기관, 공통기반, 보안관제 연계 경로 반영 여부
- 02. 트래픽 집중 및 병목 가능성에 대한 대응방안이 설계되어 있는가? [1-2-바-3-02]
- 대량 배치, 데이터 이관, 외부연계 구간 병목 분석 여부
- 대역폭, 지연시간, 패킷 손실 기준 반영 여부
- 병목 발생 시 우회, 증설, 제한 정책 반영 여부
## 4. 방화벽 및 보안그룹 정책 설계
- 01. 방화벽 정책과 보안그룹 규칙이 최소허용 원칙에 따라 설계되어 있는가? [1-2-바-4-01]
- 출발지, 목적지, 포트, 프로토콜, 허용 사유 정의 여부
- Any 정책, 과도한 포트 허용, 불필요한 양방향 허용 여부
- 업무별·시스템별 필요한 통신만 허용하도록 설계되었는지 확인
## 5. Load Balancer 및 접속경로 설계
- 01. 서비스 접속을 위한 Load Balancer 구성이 적정하게 설계되어 있는가? [1-2-바-5-01]

- 장애 시 트래픽 우회 및 자동 제외 기준 반영 여부
- 02. 외부 사용자와 내부 사용자의 접속 경로가 명확히 구분되어 있는가? [1-2-바-5-02]
- 인터넷 접속, 내부 업무망 접속, 관리자 접속 경로 구분 여부
- WAF, Reverse Proxy, API Gateway 등 보안 접점 반영 여부
- 외부 노출 서비스와 내부 서비스 분리 여부
## 6. 연계시스템 네트워크 설계

- 02. 국가 정보보안 기준 또는 발주기관 보안 기준이 설계에 반영되어 있는가? [1-2-바-7-02]

- 03. 보안 요구사항과 네트워크 설계 간 정합성이 확보되어 있는가? [1-2-바-7-03]
