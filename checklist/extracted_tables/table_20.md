# Table 20

- 단계: 1. 요구정의 단계
- 카테고리: 나. 개발SW 운영

## 1. 릴리즈 및 배포관리 요구사항
- 01. 개발SW의 운영 반영 및 배포관리 요구사항이 명확히 정의되어 있는가? [2-1-나-1-01]
- 운영 반영 대상 프로그램, 배포 대상, 배포 주기, 배포 승인 기준 정의 여부
- 정기배포, 긴급배포, 임시배포, 롤백 기준 구분 여부
- 배포 전 백업, 배포 후 정상성 점검, 배포 실패 시 원복 기준 정의 여부
- 02. 릴리즈 계획과 운영일정 간 충돌 가능성이 검토되었는가? [2-1-나-1-02]
- 업무 피크 시간, 정기점검 시간, 배치 수행 시간과 배포 일정 충돌 여부
- 서비스 중단 필요 시 사전 공지, 승인, 복구계획 정의 여부
- 배포 지연 또는 실패 시 후속 일정 영향 분석 기준 정의 여부
- 03. 배포 결과를 추적·관리할 수 있는 기준이 정의되어 있는가? [2-1-나-1-03]
- 배포 요청, 승인, 적용, 검증, 종료 이력관리 항목 정의 여부
- 배포 산출물, 배포파일, 설정파일, 변경내역 관리 기준 정의 여부
- 배포 결과와 장애·CSR·변경요청 간 추적성 확보 여부
## 2. 테스트 지원 요구사항
- 01. 운영 반영 전 테스트 지원 범위와 기준이 정의되어 있는가? [2-1-나-2-01]
- 기능시험, 회귀시험, 통합시험, 사용자 확인시험 지원 범위 정의 여부
- 테스트 환경, 테스트 데이터, 계정·권한 지원 기준 정의 여부
- 테스트 수행 주체, 지원 주체, 승인 주체 명확성 확인
- 02. 테스트 결함의 조치·재시험·승인 기준이 마련되어 있는가? [2-1-나-2-02]
- 결함 등급, 조치기한, 재시험 기준 정의 여부
- 중대 결함 발생 시 운영 반영 보류 기준 정의 여부
- 결함 조치 결과와 배포 승인 간 연계 기준 정의 여부
## 3. 장애관리 요구사항
- 01. 개발SW 운영 중 장애관리 기준이 정의되어 있는가? [2-1-나-3-01]
- 애플리케이션 오류, 배치 오류, 연계 오류, 화면 오류 등 장애유형 분류 기준 정의 여부
- 장애등급, 접수경로, 조치기한, 보고기준 정의 여부
- 중대장애 발생 시 긴급보고, 비상연락망, escalation 기준 정의 여부
- 02. 장애 처리 절차와 책임분계가 명확한가? [2-1-나-3-02]
- 장애 접수, 원인분석, 임시조치, 근본조치, 검증, 종료 절차 정의 여부
- 운영조직, 개발SW 운영 담당, 유지관리 담당, 외부 연계기관 간 역할 구분 여부
- 장애 처리 결과의 사용자 통보 및 업무부서 확인 절차 정의 여부
