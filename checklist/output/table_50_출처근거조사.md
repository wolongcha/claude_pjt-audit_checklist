## 2. RAG 기능 구현 및 검색-생성 흐름 검증

#### [3-3-나-2-01]: RAG 처리 흐름이 정상 동작하는가?
* **검토 내용**:
    * 사용자 질의 → 검색 → 근거 선택 → 생성 → 응답 흐름 정상 여부
    * 검색 결과와 생성 응답 간 데이터 전달 정상 여부
    * 검색 실패, 근거 부족, 생성 실패 시 예외처리 동작 여부
* **출처 문헌**:
    * [AI보안위협대응매뉴얼] "외부 데이터(External Data)" 정의 — "외부 데이터는 LLM의 검색, 추론, 답변 생성을 보조하기 위해 연결되는 외부 문서, 지식 저장소, 벡터 DB(Vector Database), 임베딩(Embedding) 저장소 등을 의미한다. 주로 검색 증강 생성(Retrieval-Augmented Generation, RAG)에 활용되며, 데이터 오염이나 악성 문서 주입의 주요 경로가 될 수 있다"
    * [AI보안위협대응매뉴얼] "LLM 기반 서비스는 모델 호출·응답 구조에 RAG, 내·외부 도구, 벡터 DB, 에이전트 등 다양한 구성요소가 결합된 복합 애플리케이션 형태로 발전하고 있다"
    * [감리점검해설서] SD14-1 검토항목 03 — "통합시험을 통해 내외부 시스템 간의 연계 및 구현된 시스템 간의 기능 완전성과 데이터 무결성이 확보되었는가? — 내/외부 연계/통합기능의 무결성, 데이터처리 기능의 무결성"
    * [AI보안위협대응매뉴얼] 3.6 요청 트래픽 제어 "외부 연동 보호" — "외부 API 지연이나 장애가 전체 서비스로 전파되는 것을 차단(ex) 외부 호출 타임아웃 설정)"
* **근거 및 상세내용**:
    * [AI보안위협대응매뉴얼]의 "외부 데이터" 정의는 RAG를 "검색·추론·답변 생성을 보조"하는 구조로 공식 정의하여, "질의→검색→근거선택→생성→응답"이라는 본 항목의 흐름이 RAG의 표준적 개념 정의에 부합함을 뒷받침한다.
    * [감리점검해설서] SD14-1 검토항목03의 "내/외부 연계/통합기능의 무결성", "데이터처리 기능의 무결성"은 "검색 결과와 생성 응답 간 데이터 전달 정상 여부"라는 세부 검토내용에 대응하는 전통적 통합시험 감리기준이다 — RAG의 검색(retrieval) 모듈과 생성(generation) 모듈은 별도 시스템/API로 연계되는 경우가 많으므로 이 조문이 직접 적용된다.
    * "검색 실패, 근거 부족, 생성 실패 시 예외처리"는 [AI보안위협대응매뉴얼] 3.6의 "외부 API 지연이나 장애가 전체 서비스로 전파되는 것을 차단"하는 원칙에서 근거를 찾을 수 있다 — 검색(내부 또는 외부 API) 실패가 생성 단계 전체를 중단시키지 않고 격리·처리되어야 한다는 취지가 부합한다. 다만 "근거 부족"이라는 RAG 특유의 상황(검색은 성공했으나 관련도가 낮은 경우)에 대한 별도 처리기준은 1순위 문헌에서 확인되지 않았다 — 확인 필요.

#### [3-3-나-2-02]: 검색과 생성 단계가 분리 검증 가능한가?
* **검토 내용**:
    * 검색 결과 로그 및 생성 결과 로그 분리 저장 여부
    * 검색 오류와 생성 오류의 원인분석 가능 여부
    * 검색·생성별 성능 및 품질 측정 결과 확보 여부
* **출처 문헌**:
    * [AI보안가이드북] M08(데이터 로깅·모니터링) — "원시·학습데이터 등에 대한 접근·변경 행위 로그 기록 및 정기 분석"
    * [AI보안가이드북] M09(AI시스템 로깅·모니터링) — "사용자, 단말, 시스템 등에서 발생하는 AI 입·출력정보, 접근이력 등을 로그 기록하고 정기 분석"
    * [AI보안위협대응매뉴얼] A01(부적절한 도구 설계) 점검항목 — "도구 호출 이력과 실행 결과를 기록하고, 비정상적인 도구 호출을 탐지·차단하는가"
    * [감리점검해설서] SD14-1 검토항목 06 — "시험 유형별 시나리오, 데이터, 결과 관리의 적정성"
* **근거 및 상세내용**:
    * [AI보안가이드북] M09의 "AI 입·출력정보... 로그 기록"은 AI시스템의 입력·출력을 로그로 남길 것을 요구하는데, RAG 아키텍처에서는 "입력"이 검색 단계, "출력"이 생성 단계로 물리적으로 분리되어 있으므로, 이 원칙을 적용하면 "검색 결과 로그"와 "생성 결과 로그"가 자연스럽게 분리되어 기록되어야 한다는 결론이 도출된다 — 다만 M09가 "검색"과 "생성"을 명시적으로 별도 로깅 대상으로 구분하여 규정하지는 않는다.
    * [AI보안위협대응매뉴얼]의 "도구 호출 이력과 실행 결과를 기록"하는 원칙은 검색을 "도구 호출"(RAG 검색 도구)로 간주할 경우 "검색 오류와 생성 오류의 원인분석 가능 여부"에 대한 근거가 된다 — 도구(검색) 호출 이력이 별도 기록되어야 생성 단계와 구분된 원인분석이 가능하다.
    * "검색·생성별 성능 및 품질 측정 결과"를 분리하여 확보하도록 명시적으로 요구하는 조문은 1순위 문헌에서 확인되지 않았다 — 확인 필요(로깅·모니터링의 일반원칙에서 유추될 뿐, RAG의 검색/생성 분리 평가체계를 직접 규정한 조문은 없다. 본 표 [3-3-나-6-02]와 동일한 결론).

#### [3-3-나-2-03]: 근거 기반 응답 생성이 구현되었는가?
* **검토 내용**:
    * 응답 내 근거 문서, 출처, 조항, 작성일 표시 여부
    * 근거 문서와 응답 내용 간 일치성 확인
    * 근거 없는 응답 제한 및 답변불가 처리 동작 여부
* **출처 문헌**:
    * [AI보안위협대응매뉴얼] M05(환각) 진단 방법 — "근거 문서와 응답 내용의 일치 여부 점검 — RAG나 검색 기반 응답을 사용하는 경우, 모델 응답이 실제 검색된 문서의 내용에 근거하고 있는지 확인한다. 모델이 검색 결과에 없는 내용을 추가하거나, 문서의 의미를 왜곡하여 답변하는 경우 환각으로 판단할 수 있다"
    * [AI보안가이드북] M05(환각) — "중요한 답변에 대해 출처 확인 및 근거를 제시하도록 검증 절차를 수행하는가"
    * [이용자보호가이드라인] 원칙2 — "서비스 제공자는 생성형 인공지능 산출물이 생성형 인공지능으로 생성되었음을 자율적으로 선택한 방식으로 알린다"
* **근거 및 상세내용**:
    * [AI보안위협대응매뉴얼] M05 진단방법의 "근거 문서와 응답 내용의 일치 여부 점검"은 본 항목 전체("근거 기반 응답 생성이 구현되었는가")의 검증 방법론을 그대로 제공하는 가장 직접적인 근거이며, "근거 문서와 응답 내용 간 일치성 확인"이라는 세부 검토내용과 문언이 정확히 일치한다. [AI보안가이드북] M05의 "중요한 답변에 대해 출처 확인 및 근거를 제시하도록 검증 절차를 수행"은 이를 통제기준 차원에서 보강한다.
    * "응답 내 근거 문서, 출처, 조항, 작성일 표시"라는 구체적 표시 형식(UI·응답 포맷 수준)을 규정한 조문이나, "근거 없는 응답 제한 및 답변불가 처리"를 명시적으로 요구하는 조문은 1순위 문헌에서 확인되지 않았다 — 확인 필요(M05는 "근거 제시 검증 절차"의 필요성만 규정할 뿐, 근거가 없을 때 "답변불가"로 처리하는 구체적 동작기준까지는 제시하지 않는다).

## 3. 하이브리드 검색 및 랭킹 결과 검증

    * [감리점검해설서] SD14-1 검토항목 02 — "통합시험이 계획에 따라 적정하게 실시되었는가? — 시험범위 적정성, 시험결과 정확성"

    * [감리기준] 제10조가 규정하는 종료단계 감리의 본질(과업이행 여부의 적합·부적합 최종 점검)은, "하이브리드 검색"이 사업 요구사항(과업내용)으로 정의되어 있었다면 그 구현 여부를 검증해야 한다는 절차적 근거를 일반적 수준에서 제공한다. [감리점검해설서] SD14-1의 "시험범위 적정성, 시험결과 정확성"은 이러한 검증이 통합시험 결과를 통해 확인되어야 함을 뒷받침한다.
    * "메타정보 검색과 내용기반 검색의 결합", "검색 방식별 결과 비교"라는 세부 기법은 1순위 문헌에서 확인되지 않았다 — 확인 필요.

#### [3-3-나-3-02]: 검색 랭킹 및 재정렬 결과가 적정한가?
* **검토 내용**:
    * Top-K 검색 결과 적합성 확인
    * Re-ranking 결과의 관련도 및 우선순위 적정성 확인
    * 중복 문서, 노이즈 문서, 부적절 검색결과 제거 여부
* **출처 문헌**:
    * [AI데이터가이드1권] Task별 유효성 측정지표 표 — "Top-K 정확도"를 텍스트요약(Text Summary)·객체인식(Object Detection)·이미지분류(Image Classification) 등 다수 Task의 정식 "유효성 측정지표"로 규정(예: "Text Summary 정확도 Fβ-점수 TOP-K 정확도 ROUGE-L")
    * [AI보안위협대응매뉴얼] 접근통제 정책 적용 지점 — "검색 후(Post-retrieval): 반환 문서·청크 목록 재필터·필드 마스킹"
* **근거 및 상세내용**:
    * [AI데이터가이드1권]은 "Top-K 정확도"를 AI 모델의 정식 유효성(품질) 측정지표로 명시하여, "Top-K 검색 결과 적합성 확인"이라는 세부 검토내용이 실제로 존재하는 품질지표 개념에 근거함을 뒷받침한다. 다만 이 지표는 이미지분류·객체인식·텍스트요약 등 일반 AI 모델 평가 맥락에서 제시된 것으로, RAG 검색결과에 특정하여 Top-K를 정의한 조문은 아니다 — RAG 맥락에서의 적용은 개념적 유추이다.
    * [AI보안위협대응매뉴얼]의 "검색 후(Post-retrieval): 반환 문서·청크 목록 재필터"는 "중복 문서, 노이즈 문서, 부적절 검색결과 제거"라는 세부 검토내용에 대응하는 기술적 근거를 제공한다 — 검색 이후 결과 목록을 재필터링하는 절차가 보안 통제(민감정보 필터링) 목적뿐 아니라 품질 통제(노이즈 제거) 목적으로도 준용될 수 있다.
    * "Re-ranking(재순위화)"이라는 용어 자체와 그 관련도 평가기준을 규정한 조문은 1순위 문헌에서 확인되지 않았다 — 확인 필요.

## 4. 청킹·임베딩 및 벡터DB 품질 검증

#### [3-3-나-4-01]: 청킹 결과가 문서 특성에 맞게 적용되었는가?
* **검토 내용**:
    * 기록물, 민원, 사규 등 문서 유형별 청킹 결과 확인
    * 조항·문단·첨부파일의 의미 단위 유지 여부
    * 청킹 크기, 중첩, 문맥 보존 수준 검증
* **출처 문헌**:
    * [AI보안위협대응매뉴얼] M02(벡터 DB·임베딩 유출) 발생원인 — "벡터 DB 내 임베딩·문서 청크·메타데이터에 대한 접근 권한 통제가 미흡하여 사용자별 데이터 접근 범위가 적절하지 않은 경우 발생할 수 있다"
    * [AI보안위협대응매뉴얼] 에이전트 대응방안 — "RAG 시스템을 활용하는 경우 외부 데이터와 문서 청크에 대한 검증 절차를 마련하고, 사용자 권한에 따라 접근 가능한 검색 범위를 분리해야 한다"
* **근거 및 상세내용**:
    * [AI보안위협대응매뉴얼]은 "문서 청크"를 벡터 DB의 구성요소이자 접근통제·검증 대상으로 명시적으로 인정하고 있어, "청킹"이 RAG 시스템에서 실제로 존재하는 정식 처리단계임을 뒷받침하는 근거가 된다. "RAG 시스템을 활용하는 경우 외부 데이터와 문서 청크에 대한 검증 절차를 마련"하라는 원칙은 청킹 결과물(문서 청크)의 품질이 검증 대상이 되어야 함을 일반적 수준에서 뒷받침한다.
    * 그러나 "문서 유형별 청킹 결과", "조항·문단 의미 단위 유지", "청킹 크기·중첩·문맥보존 수준"과 같은 구체적 청킹 기법·파라미터 기준은 1순위 문헌에서 확인되지 않았다 — 확인 필요(1순위 문헌은 청크를 보안 통제 대상으로만 다룰 뿐, 청킹 자체의 품질기법을 규정하는 문헌이 아니다. RAG 엔지니어링 실무 영역으로 판단된다).

#### [3-3-나-4-02]: 임베딩 품질이 검색 품질을 충족하는가?
* **검토 내용**:
    * 대표 질의 기반 유사도 검색 결과 검증
    * 임베딩 모델 적용 결과의 업무 적합성 확인
    * 임베딩 재생성 및 변경관리 절차 적용 여부
* **출처 문헌**:
    * [AI보안위협대응매뉴얼] "외부 데이터... 벡터 DB(Vector Database), 임베딩(Embedding) 저장소 등을 의미한다. 주로 검색 증강 생성(RAG)에 활용"
    * [AI보안위협대응매뉴얼] 3.2 모델 및 프롬프트 버전 관리 — "재현성 확보 및 롤백: 특정 시점의 모델·프롬프트 조합을 그대로 복원해 문제 분석, 서비스 품질 비교, 감사 대응이 가능하도록 관리", "무결성 검증: 모델 가중치, 데이터셋, 프롬프트 요소에 대해 해시 검증 및 디지털 서명 확인"
    * [지능정보기술가이드] OP-IF-11[구성 관리] 03 — "변경 등으로 인한 구성 변화가 적정하게 기록되고 관리되고 있는가? — 변경에 따른 구성 변경의 적정성, 구성 변경에 대한 이력관리의 적정성"
* **근거 및 상세내용**:
    * [AI보안위협대응매뉴얼]의 "임베딩 저장소"가 RAG의 핵심 구성요소로 정의되어 있다는 점은 "임베딩 품질"이 RAG 시스템 품질의 필수 구성요소임을 개념적으로 뒷받침한다. 3.2절의 "모델 및 프롬프트 버전 관리" 원칙(재현성·롤백·무결성 검증)은 비록 "임베딩 모델"을 별도 명시하지는 않으나, 관리 대상 "모델"의 정의에 "학습 로그, 가중치 파일, 검증 결과"를 포함하고 있어 임베딩 모델에도 준용될 수 있는 버전관리 원칙으로 판단된다 — 임베딩 모델 교체·재학습 시에도 이력관리·재현성 확보가 필요하다는 유추가 가능하다.
    * [지능정보기술가이드] OP-IF-11의 "구성 변경에 대한 이력관리의 적정성"은 "임베딩 재생성 및 변경관리 절차 적용 여부"라는 세부 검토내용에 직접 대응하는 전통적 형상관리 감리기준이다(운영단계 기준의 유추 적용).
    * "대표 질의 기반 유사도 검색 결과 검증"이라는 구체적 임베딩 품질 검증 방법론과, "업무 적합성"을 판단하는 기준은 1순위 문헌에서 확인되지 않았다 — 확인 필요.

#### [3-3-나-4-03]: 벡터DB 적재 및 현행화가 정상적으로 수행되었는가?
* **검토 내용**:
    * 벡터DB 적재 성공률 및 누락 데이터 확인
    * 메타데이터, 권한정보, 문서번호, 작성일 등 필터정보 적재 여부
    * 재색인, 삭제, 갱신 처리 결과 확인
* **출처 문헌**:

## 6. Golden Set 기반 AI 성능평가 검증

    * [감리점검해설서] SD14-1 검토항목 01 — "시험환경이 실제 운영환경을 반영하여 구축되고 시험 준비가 완료 되었는가? — 시험계획의 적정성(시험대상/전제사항/품질목표), 시험데이터 준비현황"

#### [3-3-나-6-02]: 검색·생성 분리 평가 결과가 확보되었는가?
* **검토 내용**:

    * 생성 정확도, 근거 일치성, 응답 일관성 평가 결과 확인
    * 검색 오류와 생성 오류 원인분류 결과 확인
* **출처 문헌**:
    * [AI데이터가이드3권] 질의응답(Question Answering) Task 측정지표 표 — 원문(표 병합 추출 텍스트, 셀 구분 유실 상태): "ACC LLaMA2-7B(JCommonSenseQA) 55.52% 이상 LLaVa 80% 이상 RAG 92% 이상 Recall@100 LLaMA 2 75 이상 F1 점수..." — "RAG"·"Recall@100"·"92% 이상" 수치가 함께 명시되어 있어 RAG 시스템에 대해 Recall@100 기준 92% 이상의 정량목표가 예시로 제시된 것으로 판단됨(PDF 표 추출 과정에서 열 구분이 유실되어 정확한 행렬 대응은 원본 표 이미지 대조가 필요함을 밝혀둔다)

    * [AI보안위협대응매뉴얼] M05 진단방법 — "근거 문서와 응답 내용의 일치 여부 점검", "반복 질의를 통한 응답 일관성 점검"
* **근거 및 상세내용**:
    * [AI데이터가이드3권]의 "RAG... Recall@100... 92% 이상" 기재는 "검색 정확도, 재현율... 등 검색 평가 결과"라는 세부 검토내용에 대한 구체적이고 정량적인 근거를 제공하는 가장 직접적인 자료이다 — Recall@100이라는 정보검색(IR) 분야의 표준 재현율 지표가 RAG 평가에 실제로 적용된 사례로 확인된다(다만 위와 같이 원본 PDF 표의 행/열 구분이 텍스트 추출 과정에서 유실되어 있어 정확한 지표-모델-수치의 1:1 대응관계까지는 완전히 확정하지 못하였다). [AI데이터가이드1·2권]의 "정확도, 정밀도, 재현율" 표준지표는 이를 일반 AI 모델평가 맥락에서 보강한다.
    * [AI보안위협대응매뉴얼] M05의 "근거 문서와 응답 내용의 일치 여부 점검"과 "반복 질의를 통한 응답 일관성 점검"은 "생성 정확도, 근거 일치성, 응답 일관성 평가"라는 세부 검토내용에 직접 대응하는 진단 방법론이다.
    * "MRR(Mean Reciprocal Rank)"과 "Zero-hit"이라는 정보검색 특유의 지표를 명시적으로 정의·요구한 조문은 1순위 문헌에서 확인되지 않았다 — 확인 필요(Recall@100은 확인되었으나 MRR 자체는 1순위 문헌에 없음). "검색 오류와 생성 오류 원인분류"라는 이원화된 오류분류체계 역시 확인되지 않았다 — 확인 필요.
