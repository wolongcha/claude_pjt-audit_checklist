## 1. 데이터 전환 대상 식별

#### [1-1-라-1-01]: 클라우드 전환 대상 데이터가 누락 없이 식별되어 있는가?
* **검토 내용**:
    * 업무 DB, 테이블, 파일, 첨부파일, 로그, 기준정보, 이력 데이터 식별 여부
    * 전환 대상 데이터와 제외 대상 데이터의 구분 여부
    * 제외 대상 데이터의 사유와 후속 처리방안 정의 여부
* **출처 문헌**:
    * 「감리수행가이드」 4.3.1 시스템개발사업(구조적·정보공학적 모델) 분석단계 데이터베이스 영역 기본점검항목 1. "현행 업무관련 데이터를 충분히 식별하였는지 여부"
    * 「감리점검해설서」 SD22-3-A1 (시스템개발/객체지향·컴포넌트기반 모델/분석설계/데이터베이스) 검토항목 01. "현행업무와 관련된 데이터 및 분산 구조가 식별되었는가?" — 하위 검토요소: 업무처리를 위한 입력/출력 데이터, 관련업무 및 타 시스템과의 연계 데이터, 데이터베이스 분산 구조
    * 「감리점검해설서」 SD12-3-G1 검토항목 08. "기존 데이터에 대한 전환 계획이 수립되었는가?" 하위 검토요소 중 "전환 데이터 및 우선순위"
* **근거 및 상세내용**:
    * 감리기준 상 데이터베이스 영역의 첫 번째 기본점검항목이 "현행 업무관련 데이터의 충분한 식별"로 설정되어 있어, 전환(이관) 대상 데이터를 누락 없이 식별하는 것이 감리의 기본 관점임을 뒷받침한다.
    * SD22-3-A1은 식별 대상을 "입력/출력 데이터", "타 시스템 연계 데이터", "분산 구조"로 세분화하고 있어, 검토내용의 "업무 DB, 테이블, 파일, 로그, 기준정보" 등 유형별 식별 요구와 "전환 대상/제외 대상 구분" 요구의 근거가 된다.
    * 다만 "첨부파일·로그·이력데이터"별 세부 식별, "제외 대상 사유 및 후속처리방안"의 문서화 요건까지 구체적으로 명시한 문구는 확인되지 않아, 일반원칙(데이터 식별의 충분성) 수준에서 근거를 확인함.

#### [1-1-라-1-02]: 데이터 전환 대상과 업무·시스템 간 연관관계가 정의되어 있는가?
* **검토 내용**:
    * 업무 기능별 사용 데이터 매핑 여부
    * 애플리케이션, 배치, 연계시스템에서 참조하는 데이터 식별 여부
    * 기준정보, 마스터 데이터, 거래 데이터 간 선후행 관계 확인 여부
* **출처 문헌**:
    * 「감리점검해설서」 SD22-3-A1 하위 검토요소 "관련업무 및 타 시스템과의 연계 데이터"
    * 「구축·운영지침」 [별지 제2호서식] 상호운용성 등 기술평가표, "1-다. 정보시스템 통합성" — "통합대상 기존 업무절차, 응용기술, 데이터 및 정보시스템을 분석·기술하였는가?"
* **근거 및 상세내용**:
    * SD22-3-A1은 전환 대상 데이터 식별 시 "관련업무 및 타 시스템과의 연계 데이터"를 별도 검토요소로 명시하여, 데이터와 업무·연계시스템 간 연관관계 파악을 감리 관점으로 제시하고 있다.
    * 「구축·운영지침」 별지 제2호서식은 정보시스템 간 통합 시 "기존 업무절차, 응용기술, 데이터 및 정보시스템"을 함께 분석·기술하도록 요구하여, 데이터와 업무·시스템 간 연관관계를 사업계획 단계에서 명시적으로 검토하도록 하는 근거가 된다.
    * "기준정보·마스터데이터·거래데이터 간 선후행 관계"라는 구체적 표현은 확인된 출처에 없어, 데이터-업무 연관관계 정의라는 상위 원칙 수준에서 근거를 확인함.

#### [1-1-라-1-03]: 현행 데이터 아키텍처가 충분히 파악되어 있는가?
* **검토 내용**:
    * 현행 DB 구조, 테이블 구조, 데이터 흐름, 연계 구조 파악 여부
    * 데이터 발생·저장·활용·보관·폐기 흐름 확인 여부
    * 현행 데이터 구조와 목표 클라우드 데이터 구조 간 차이 식별 여부
* **출처 문헌**:
    * 「클라우드점검가이드」/「지능정보기술가이드」 검토항목 3(코드 [ISO1-2-B5]) "행정망과 인터넷망 사이에 데이터 전환이 필요한가"
    * 「감리수행가이드」 4.3.1 분석단계 데이터베이스 영역 기본점검항목 2. "현행 시스템의 데이터 현황을 충분히 분석하였는지 여부", 4. "데이터 흐름 정의가 명확한지 여부"
* **근거 및 상세내용**:
    * [ISO1-2-B5]의 "필요성" 항목 원문: "현행 시스템에 대한 데이터 아키텍처가 충분히 파악되지 않은 경우, 이를 토대로 내외부 망 사이의 데이터 관리 대상이 구분되지 않아 데이터 연동 문제로 클라우드 도입이 허용되지 않는 문제가 발생할 수 있다. 따라서 현행 시스템의 업무 기능을 기반으로 데이터 아키텍처가 충분히 파악되었는지 확인하는 것이 필요하다." — 검토항목의 취지와 문구가 사실상 동일하여 가장 직접적인 근거임.
    * 「감리수행가이드」는 데이터베이스 영역 분석단계에서 "현행 시스템 데이터 현황 분석"과 "데이터 흐름 정의"를 별도 기본점검항목으로 규정하여, DB/테이블 구조 및 데이터 흐름 파악 요구의 근거가 된다.
    * "목표 클라우드 데이터 구조와의 차이 식별"이라는 클라우드 전환 특화 문구는 확인된 출처에 직접 명시되어 있지 않으나, [ISO1-2-B5]가 "클라우드 도입 허용 여부"와 아키텍처 파악을 직접 연결하고 있어 취지상 포함되는 것으로 판단됨.

## 2. 데이터 전환 범위 및 기준 정의

#### [1-1-라-2-01]: 데이터 전환 범위가 업무 요구사항에 맞게 정의되어 있는가?
* **검토 내용**:
    * 전체 이관, 부분 이관, 기간별 이관, 업무별 이관 범위 정의 여부
    * 운영 데이터, 과거 데이터, 로그 데이터, 첨부파일 포함 여부
    * 전환 범위가 애플리케이션 전환 범위와 일치하는지 확인
* **출처 문헌**:
    * 「감리점검해설서」 SD12-3-G1(설계/데이터베이스) 목적/필요성 서술 및 하위 검토요소 "전환 데이터 및 우선순위"
    * 「감리점검해설서」 SD22-3-F1(분석설계/데이터베이스, 객체지향모델) 하위 검토요소 "전환 데이터 및 우선순위 식별"
* **근거 및 상세내용**:
    * SD12-3-G1의 "필요성" 원문: "전환대상 범위결정에서부터 최종 전환이행까지의 과정에 대해서 충분한 사전분석 및 계획이 수립되지 않는다면, 시행착오와 전환 전, 후 데이터간의 불일치로 인한 시스템의 신뢰성 저하를 초래할 수 있다." — "전환대상 범위결정"을 감리 점검의 핵심 요소로 명시하여, 데이터 전환 범위 정의 요구의 직접적 근거가 된다.
    * 하위 검토요소 "전환 데이터 및 우선순위(식별)"은 이관 대상의 범위·우선순위를 사전에 정해야 함을 의미하며, 전체/부분/업무별 이관 범위 구분이라는 검토내용과 부합한다.
    * "애플리케이션 전환 범위와의 일치 확인"이라는 클라우드 전환사업 특유의 요구는 확인된 1차 출처에 별도로 명시되어 있지 않음(일반 SDLC 감리기준은 데이터 전환과 응용 전환을 각각 별개 점검항목으로 다룸). 이 부분은 애플리케이션 영역(Table 2 등)과의 정합성 관점에서 별도 확인이 필요할 수 있음.

## 3. 데이터 이관 방식 요구사항

#### [1-1-라-3-01]: 데이터 특성에 맞는 이관 방식이 검토되어 있는가?
* **검토 내용**:
    * DB Export/Import, ETL, 파일 이관, API 이관, DB 복제 방식 검토 여부
    * 대용량 데이터, 첨부파일, 로그 데이터 등 유형별 이관 방식 구분 여부
    * 업무중단 허용시간과 이관 방식 간 정합성 확인
* **출처 문헌**:
    * 「감리점검해설서」 SD12-3-G1/SD22-3-F1 하위 검토요소 "전환 매핑규칙 및 프로그램의 개발"
    * 「클라우드점검가이드」/「지능정보기술가이드」 [표 3-9]/[표 3-14] "G-클라우드 전환을 위한 기관간 역할" 중 "데이터 이관" 활동
    * 「지능정보기술가이드」 [그림 3-6] "DB서버 이중화 방식" 중 "네트워크를 통한 복제 방식", "디스크 공유 방식(Unix만 가능)"
* **근거 및 상세내용**:
    * SD12-3-G1/SD22-3-F1은 전환계획 수립 시 "전환 매핑규칙 및 프로그램의 개발"을 검토요소로 규정하여, 데이터 특성에 맞는 이관(전환) 방식과 그 구현 방법이 사전에 검토·정의되어야 함을 뒷받침한다.
    * 「클라우드점검가이드」 등은 G-클라우드 전환 절차상 "데이터 이관"을 별도의 수행활동으로 규정하고 있어, 이관 작업 자체가 계획적으로 검토되어야 하는 감리 대상임을 확인해 준다.
    * [그림 3-6]은 DB 이중화(복제) 구현 방식을 "네트워크를 통한 복제", "디스크 공유 방식" 등으로 예시하고 있어 'DB 복제' 방식 검토의 근거가 된다.
    * 다만 "DB Export/Import, ETL, API 이관" 등 구체적 기술 목록 전체를 열거한 원문은 확인되지 않았으며, "업무중단 허용시간과 이관 방식 간 정합성"에 대한 명시적 문구도 확인되지 않음 — 이관 방식 검토 필요성이라는 상위 원칙 수준에서 근거를 확인함.

## 4. 데이터 동기화 대상 및 필요성 검토

#### [1-1-라-4-01]: 클라우드 전환 과정에서 데이터 동기화가 필요한 대상이 식별되어 있는가?
* **검토 내용**:
    * 실시간 동기화 대상과 배치성 동기화 대상 구분 여부
    * 운영 중 병행운영이 필요한 데이터 식별 여부
    * 동기화 제외 대상과 제외 사유 정의 여부
* **출처 문헌**:
    * 「클라우드점검가이드」 [표 3-8] / 「지능정보기술가이드」 [표 3-7] "G-클라우드 업무시스템 설계단계 수행활동" 중 "인터넷망-행정업무망 간 데이터 동기화 방안"
* **근거 및 상세내용**:
    * 해당 표는 업무시스템 설계단계의 수행활동으로 "인터넷망-행정업무망 간 데이터 동기화 방안"을 명시하고, 세부 항목으로 "개별 시스템의 일반적인 데이터 동기화(배치성 단방향 동기화)", "용도별 DB서버 분리를 통한 동기화(배치성 양방향 동기화)", "망연동 정보시스템 구현(소켓통신)"을 제시하고 있다. 이는 동기화가 필요한 대상(시스템·데이터)을 사전에 식별하고 동기화 유형(단방향/양방향, 배치성)을 구분해야 한다는 검토내용의 직접적 근거가 된다.
    * "실시간 동기화"라는 표현 자체는 확인된 출처에 없으며(출처는 "배치성" 동기화 중심으로 기술), "병행운영 필요 데이터 식별", "동기화 제외 대상 및 사유" 관련 문구도 별도로 확인되지 않음. 동기화 대상 식별의 필요성이라는 원칙은 근거가 확보되나, 실시간/병행운영/제외기준의 세부 내용은 근거가 제한적임.

#### [1-1-라-4-02]: 망간 또는 영역 간 데이터 동기화 필요성이 검토되었는가?
* **검토 내용**:
    * 행정망–인터넷망, 내부망–외부망, 운영망–DR망 간 데이터 전환·동기화 필요성 확인
    * 망간 데이터 흐름, 보안통제, 승인 절차 식별 여부
    * 데이터 동기화가 필요한 구간과 불필요한 구간 구분 여부
* **출처 문헌**:
    * 「클라우드점검가이드」/「지능정보기술가이드」 검토항목 3(코드 [ISO1-2-B5]) "행정망과 인터넷망 사이에 데이터 전환이 필요한가"
    * 「구축·운영지침」 [별지 제2호서식] 상호운용성 등 기술평가표, "연계시스템 간 물리적 환경을 검토하였는가? * 설치 위치, 인프라(서버, 스토리지 등) 및 네트워크(행정망, 인터넷망, 전용망 등) 구성 등"
* **근거 및 상세내용**:
    * [ISO1-2-B5]는 검토항목명 자체가 "행정망과 인터넷망 사이에 데이터 전환이 필요한가"로, 목적에서 "내부망에서 관리하는 데이터와 외부 인터넷망에서 관리하는 데이터 간에 데이터 연동이나 전환이 필요한지 검토"한다고 명시하여, 망간 데이터 동기화 필요성 검토라는 항목과 사실상 동일한 취지를 갖는다.
    * 「구축·운영지침」 별지 제2호서식은 연계시스템 검토 시 행정망·인터넷망·전용망 등 네트워크 구성을 별도로 확인하도록 하여, 망 구간별 데이터 흐름 검토의 제도적 근거가 된다.
    * "운영망-DR망 간 동기화", "보안통제·승인 절차"에 대한 구체적 문구는 확인된 출처에 없으며, 이 부분은 보안 요구사항([1-1-라-10-01])과 연계하여 판단할 필요가 있음.

## 5. 동기화 방식 및 주기 요구사항

#### [1-1-라-5-01]: 데이터 특성에 맞는 동기화 방식이 검토되어 있는가?
* **검토 내용**:
    * CDC, 로그 기반 복제, DB 복제, ETL, API, 파일 동기화 방식 검토 여부
    * 실시간, 준실시간, 배치성 동기화 방식 구분 여부
    * 데이터량, 변경 빈도, 업무 중요도에 따른 방식 차등 적용 여부
* **출처 문헌**:
    * 「클라우드점검가이드」 [표 3-8] / 「지능정보기술가이드」 [표 3-7] "인터넷망-행정업무망 간 데이터 동기화 방안"(배치성 단방향/양방향 동기화)
    * 「지능정보기술가이드」 [그림 3-6] "DB서버 이중화 방식" 중 "네트워크를 통한 복제 방식"
* **근거 및 상세내용**:
    * 위 두 자료는 각각 망간 동기화 방식(배치성 단방향·양방향)과 DB서버 간 복제 방식(네트워크 복제, 디스크 공유)을 구체적으로 예시하여, 데이터 특성·환경에 따라 동기화 방식이 달라져야 하고 이를 사전에 검토해야 한다는 원칙의 근거가 된다.
    * 다만 "CDC(Change Data Capture)", "로그 기반 복제", "ETL", "API 동기화"라는 개별 기술 명칭과 "실시간/준실시간" 구분, "데이터량·변경빈도·업무중요도에 따른 차등 적용" 기준은 확인된 1차 출처 어디에서도 명시적으로 발견되지 않았다. 이 세부 기술 목록에 대해서는 "확인 필요"로 표시하며, 동기화 방식 검토 자체의 필요성만 상기 출처로 근거를 확인함.

#### [1-1-라-5-02]: 복제 방향과 운영 구조가 요구사항 단계에서 정의되어 있는가?
* **검토 내용**:
    * 단방향 복제, 양방향 복제, Active-Standby, Active-Active 구조 검토 여부
    * 원천 시스템과 대상 시스템의 역할 정의 여부
    * 병행운영 기간 중 데이터 입력·수정 기준 정의 여부
* **출처 문헌**:
    * 「지능정보기술가이드」 [그림 3-6] "DB서버 이중화 방식" — Master-Slave(1:1), Master-Slave(1:N), Master-Master(Replication), Master-Master(Disk-Shared) 4가지 구성
    * 「클라우드점검가이드」 [표 3-8] / 「지능정보기술가이드」 [표 3-7] "배치성 단방향 동기화", "배치성 양방향 동기화"
* **근거 및 상세내용**:
    * [그림 3-6]은 G-클라우드 환경의 DB서버 이중화 방식을 4가지로 제시하며, 각 방식별로 "(읽기) Active-Active / (쓰기) Active-Standby" 또는 "(읽기)(쓰기) Active-Active" 구조와 "네트워크를 통한 복제 방식", "디스크 공유 방식" 등 구현 방식을 명시한다. 검토내용에 기재된 "Active-Standby, Active-Active 구조"라는 용어가 출처 원문에 그대로 사용되고 있어, 가장 직접적이고 구체적인 근거 자료이다.
    * [표 3-8]/[표 3-7]의 "배치성 단방향/양방향 동기화"는 검토내용의 "단방향 복제, 양방향 복제" 구분과 대응된다.
    * "원천-대상 시스템 역할 정의", "병행운영 기간 중 입력·수정 기준"에 대한 별도 문구는 확인되지 않았으나, Master-Slave 구조 자체가 "Master(Read/Write)"·"Slave(Read)"처럼 역할을 구분하고 있어 취지상 관련된다고 판단됨.

## 6. 원천·대상 데이터 매핑 및 변환 기준

#### [1-1-라-6-01]: 원천 데이터와 목표 클라우드 데이터 간 매핑 기준이 정의되어 있는가?
* **검토 내용**:
    * 테이블·컬럼 단위 매핑 정의 필요성 확인
    * 데이터 타입, 길이, 문자셋, 코드값, 날짜 형식 차이 식별 여부
    * 매핑 불가 항목과 예외 처리 기준 정의 여부
* **출처 문헌**:
    * 「감리점검해설서」 SD12-3-G1/SD22-3-F1 하위 검토요소 "전환 매핑규칙 및 프로그램의 개발"
    * 「감리점검해설서」 SD15-1(전개/운영준비) 주요검토대상산출물 "09. 데이터매핑정의서"
    * 「구축·운영지침」 [별지 제2호서식] "2-나. 데이터 표준화" — "공동활용 대상 데이터 연동을 위한 메타 데이터 체계, 데이터 매핑규칙 등을 기술하였는가?"
* **근거 및 상세내용**:
    * SD12-3-G1/SD22-3-F1은 데이터 전환계획의 핵심 요소로 "전환 매핑규칙"을 명시하고 있으며, SD15-1은 산출물로 "데이터매핑정의서"를 직접 지정하고 있어, 원천-대상 데이터 간 매핑 기준 수립이 감리에서 확인해야 할 필수 산출물임을 뒷받침한다.
    * 「구축·운영지침」 별지 제2호서식의 데이터 표준화 항목도 "메타데이터 체계, 데이터 매핑규칙"을 명시적으로 요구하여 매핑기준 정의의 제도적 근거가 된다.
    * "테이블·컬럼 단위", "데이터 타입·길이·문자셋·코드값·날짜형식" 등 세부 기술 요소는 확인된 출처에 구체적으로 열거되어 있지 않으며, "매핑규칙"이라는 상위 개념 수준에서 근거를 확인함.

#### [1-1-라-6-02]: 데이터 변환·정제 기준이 요구사항에 포함되어 있는가?
* **검토 내용**:
    * 코드 변환, 형식 변환, 암호화·복호화 적용 기준 확인
    * 오류값, 누락값, 중복값 처리 기준 확인
* **출처 문헌**:
    * 「감리점검해설서」 SD12-3-G1/SD22-3-F1 하위 검토요소 "전환 매핑규칙 및 프로그램의 개발", "예외 데이터 처리 규칙"
* **근거 및 상세내용**:
    * "전환 매핑규칙"에는 통상 코드체계·형식이 상이한 데이터 간 변환 규칙이 포함되는 개념이며, "예외 데이터 처리 규칙"은 오류값·누락값 등 정상 매핑이 되지 않는 데이터의 처리기준을 의미하므로, 데이터 변환·정제 기준 수립 필요성의 근거로 볼 수 있다.
    * 다만 "코드 변환/형식 변환/암호화·복호화"를 각각 구분하여 명시한 문구, "오류값·누락값·중복값"을 항목별로 구분한 문구는 확인된 1차 출처에서 발견되지 않았다. 암호화·복호화 관련 근거는 「구축·운영지침」 제8조(보안성 검토 및 보안관리)의 개인정보 안전성 확보조치 규정([1-1-라-10-01] 참조)과 연계될 수 있으나, 데이터 변환 맥락에서 이를 직접 규정한 문구는 아니므로 이 항목은 부분적으로 "확인 필요"로 표시함.

## 7. 데이터 정합성 검증 요구사항

#### [1-1-라-7-01]: 데이터 이관 전후 정합성 검증 기준이 정의되어 있는가?
* **검토 내용**:
    * 건수, 합계, 키값, 상태값, 참조관계 비교 기준 확인
    * 테이블별·업무별·중요 데이터별 검증 수준 차등 적용 여부
    * 정합성 검증 합격 기준과 예외 승인 기준 정의 여부
* **출처 문헌**:
    * 「클라우드점검가이드」 검토항목 13 / 「지능정보기술가이드」 검토항목 19 "데이터 이관계획에 따라 데이터를 이관하고 검증이 이루어졌는가?"
    * 「감리점검해설서」 SD12-3-G1/SD22-3-F1 하위 검토요소 "기존 데이터 및 전환 데이터의 검증(사전/사후 검증)"
    * 「감리점검해설서」 SD15-1-B1 "기존 데이터 전환 수행 및 결과의 적정성 검증"; SD15-1-C1 "시스템 오픈 전후 데이터의 일관성 유지"
    * 「감리수행가이드」 4.3.1 전개단계 운영준비 "초기데이터 구축 및 데이터 전환/검증을 적정하게 수행하였는지 여부"
* **근거 및 상세내용**:
    * 「클라우드점검가이드」/「지능정보기술가이드」의 해당 검토항목은 "기존 시스템의 데이터를 데이터이관계획에 따라 수행하고, 데이터의 누락·훼손 없이 이관되었는지에 대한 검증 작업이 필요하다"고 명시하여, 이관 전후 데이터 정합성(누락·훼손 여부) 검증이 감리의 핵심 점검사항임을 직접적으로 뒷받침한다.
    * SD12-3-G1/SD22-3-F1의 "사전/사후 검증", SD15-1-C1의 "데이터 일관성 유지"는 이관 전(사전)·후(사후) 비교검증이라는 검토내용의 취지와 부합한다.
    * "건수·합계·키값·상태값·참조관계"별 구체적 비교기준, "테이블별·업무별 차등 검증 수준", "예외 승인 기준"이라는 세부 표현은 확인된 출처에 없으며, "검증 작업의 필요성"이라는 상위 원칙 수준에서 근거가 확인됨.

## 8. 오류·예외·충돌 처리 기준

#### [1-1-라-8-01]: 데이터 이관 오류와 예외 데이터 처리 기준이 정의되어 있는가?
* **검토 내용**:
    * 형식 오류, 코드 불일치, 누락값, 중복값 처리 기준 확인
    * 보정, 제외, 재처리, 수작업 처리 기준 정의 여부
    * 예외 데이터 승인 및 이력관리 기준 확인
* **출처 문헌**:
